# 投流统计平台 · 管理端（前端）

按《投流统计平台-前端技术方案》（TC-ADP-FE-TS-001 V1.3）实现的**管理端**独立工程：登录、`/admin` 单页五页签（用户管理、厂商管理、模拟参数、字典配置、操作日志）、模拟数据生成与调节。
默认使用**前端 Mock 数据**（axios 自定义 adapter + localStorage，刷新/重置可恢复初始状态）；也可一键切换**真实后端**（见「数据模式与真实后端」）。

## 快速开始

```bash
pnpm install
pnpm dev          # http://127.0.0.1:5173
```

| 账号 | 密码 | 身份 | 说明 |
| --- | --- | --- | --- |
| `admin` | `admin123` | 系统管理员 | 可进入管理端全部功能 |
| `user01` | `user123` | 普通用户 | 登录后落到 403 说明页（管理端仅管理员可访问） |

> 登录失败 3 次锁定 60 秒；令牌存 sessionStorage，关闭标签页即失效。

## 交付范围

| 模块 | 内容 |
| --- | --- |
| 登录 | 账号密码登录、失败锁定、演示账号一键填充、登录后按身份跳转 |
| 布局 | 深蓝侧边栏 + 顶栏（面包屑、模拟数据标识、账号退出）、403 / 404 |

| 厂商管理 | 编码（全局唯一）、名称、所属平台、联系人、电话（脱敏，仅管理员可查看完整）、状态、备注；被计划引用（关联计划数 > 0）只能停用不能删除 |

## 模拟数据生成规则（技术方案 4.5.4）

- 按计划排期逐日生成：当日曝光量 = 目标总曝光量 × 当日曲线权重 ×（1 ± 15% 波动）；
- 曲线支持均匀、前低后高、前高后低、周末加权，权重归一化；
- 曝光人数 = 曝光量 ÷ 人均频次（≤ 曝光量）；点击人数 = 曝光人数 × 点击率（≤ 曝光人数）；消耗 = 曝光量 ÷ 1000 × 千人成本；
- 地域 / 性别 / 年龄三个维度按比例拆分，使用**最大余数法**取整，各维度合计严格等于当日曝光量；
- 随机种子 + 计划编码参与生成，**同一参数每次生成结果一致**，便于复现与验收；
- 固定种子、目标总曝光量、点击率、千人成本、频次、人群比例可调；点击率限制 (0, 20]%，千人成本 > 0，比例合计 = 100%；
- 完成率统一口径：**实际曝光量 ÷ 计划目标曝光量**。

## 演示数据说明

预置项目「2026 年太仓分公司全域融数」与三条计划；主计划「全域曝光 · 双 11 返场」生成后：

- 实际曝光量 **17,125,369**、目标曝光量 16,880,000、完成率 **101.45%**；
- 曝光人数约 **19.7 万**、点击率 **1.15%**（对应技术方案 12.3 的 196,942 与 1.15% 口径）。

> 文档 12.3 中 196,942 恰等于 17,125,369 × 1.15%，与「曝光人数不可由曝光量推算」及默认频次 65 存在矛盾。本项目按“曝光人数 = 曝光量 ÷ 频次”自洽生成，演示数据使用频次 87 + 种子搜索校准，使总曝光量精确命中 17,125,369、曝光人数约 19.7 万。

## 数据模式与真实后端

### Mock 模式（默认，演示用）

- 启动：`pnpm dev`（`.env` 中 `VITE_USE_MOCK=true`）；
- 数据入口：`src/mock/adapter.ts`（axios 自定义 adapter），持久化 key：`adflow.admin.mock.db.v1`（localStorage）；
- 演示账号 `admin/admin123`、`user01/user123`，可「重置演示数据」恢复初始状态。

### 真实后端模式（管理页接后端 API）

- 启动：`pnpm dev:backend`（= `vite --mode backend`），先复制 `.env.backend.example` 为 `.env.backend` 并按团队环境填写：
  - `VITE_USE_MOCK=false`
  - `VITE_API_PROXY_TARGET=http://YOUR_BACKEND_HOST:3000`
  - Vite 开发服务器把 `/api` 代理到后端，避免跨域；`.env.backend` 含内网地址，**不要提交到仓库**（已在 `.gitignore`）；
- 登录：使用后端管理员账号（前端不保存密码；账号密码由后端管理员提供，请勿写入仓库）；
- 适配层：`src/api/backend.ts` 负责后端字段 ↔ 前端模型映射，`src/api/{auth,system,campaign}.ts` 按 `USE_MOCK` 自动分流，五个页签视图代码不变。主要映射：
  - 登录 `username` → 账号、`displayName` → 姓名；
  - 列表统一 `data:{items,total}` → 前端 `Paged{list,total}`；
  - `completionRate`/`clickRate` 后端为 0-1 小数 → 前端百分比；
  - `ctr` 后端为 0-0.2 小数 ↔ 前端 0-20 (%)；
  - 曲线 `uniform|front_load|back_load|weekend` ↔ 均匀/前低后高/前高后低/周末加权；
  - 随机种子字符串 → 后端整数 seed；`campaignCount` → 关联计划数；
- 页面会显示「真实后端」标识与后端数据提示，重置演示数据按钮禁用。

### 后端缺口与前端降级

| 能力 | 真实后端情况 | 管理端处理 |
| --- | --- | --- |
| 字典配置 | 无接口 | 展示前端内置口径，只读，保存时提示不支持 |
| 模拟参数清空 | 无接口 | 按钮禁用 |
| 常用方案 | 无接口 | 存浏览器 localStorage（`adflow.real.mock-presets.v1`） |
| 调节记录 | 无专用接口 | 由 `GET /logs?action=mock_generate` 反推，参数从 `mock-profile` 补全 |
| 演示数据重置 | 无接口 | 按钮禁用 |

## 已知限制

- 本工程只覆盖管理端；计划列表、发布向导、详情、数据回收、看板、报表中心属于业务端范围，不在本仓库实现；
- 普通用户登录后进入 403 说明页，不提供业务端占位页面；
- 模拟参数通过「生成」自动写入计划 Profile；常用方案单独管理，暂无单独“保存为计划参数”入口（避免与生成动作混淆）。
